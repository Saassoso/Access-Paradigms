# Realisation
### 1. Configuration Assessment
- **Verified:** Your Service Account (`n8n-iam-sync@...`) is created and enabled. Its Unique ID is `112958710790097611668`.
- **Verified:** Your OAuth 2.0 Client (`keycloak-idp-google`) is active. This is correct for the Keycloak Identity Provider integration (OIDC Broker).
- **Critical Pushback:** The IAM permissions shown only grant access to Google Cloud Platform resources. 
	- Being an "Owner" of the GCP project does **not** give the Service Account permission to create or manage users in Google Workspace.
### 2. Immediate Action Items (Google Workspace & n8n)
To authorize n8n to create your "Bureau 1" users via this Service Account, you must execute the following steps.
1. **Generate the JSON Key (GCP Console):**
    - Go to the **Keys** tab under your `n8n-iam-sync` Service Account details.
    - Click **Add Key > Create new key > JSON**.
    - Immediately store this JSON file securely in HashiCorp Vault. n8n will use this to authenticate.
     ![](images/11-5-2026.png)
	    - [[Notes/Activating Services account key creation]]
	    - [[Notes/Deploy Hashicorp Vault]]
	    - [[Deploy Vaultwarden Password manager]]
2. **Configure Domain-Wide Delegation (Google Workspace Admin Console):**
    - Log in to `admin.google.com` using your break-glass or admin account.
    - Navigate to **Security > Access and data control > API controls > Manage Domain Wide Delegation**.
    - Click **Add new**.
    - **Client ID:** Enter the Unique ID of your Service Account: `112958710790097611668`.
    - **OAuth Scopes:** You must grant it the exact permissions n8n needs to manage users. Enter:
        
        `https://www.googleapis.com/auth/admin.directory.user` (add `, https://www.googleapis.com/auth/admin.directory.group` if n8n also manages groups).
        
3. **Enable Admin SDK (GCP Console):**
    
    - Search for "Admin SDK API" in the Google Cloud search bar and verify its status is **Enabled**.
        

### 3. Readiness for GCPW (Virtual Machine)

Do not proceed with the GCPW installation on your cloned Windows VM until you have successfully executed the following test:

1. Create a test user in Keycloak (e.g., `user-basic-01@google.charif-labs.tech`).
    
2. Verify the n8n webhook triggers and the workflow uses the JSON key to successfully create that exact user in Google Workspace.
    

Once the identity flows automatically from Keycloak to Google Workspace without manual intervention, you may proceed with sanitizing the cloned VM (`dsregcmd /leave`, Sysprep) and installing GCPW as outlined previously.
