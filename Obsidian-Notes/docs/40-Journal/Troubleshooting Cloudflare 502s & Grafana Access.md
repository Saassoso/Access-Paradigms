# Operational Runbook: Edge Routing & Application Access

## 🚨 Issue 1: Cloudflare 502 Bad Gateway on Application Subdomains
**Symptom:** Accessing `n8n.charif-labs.tech` or `grafana.charif-labs.tech` returns a Cloudflare 502 Bad Gateway error, even though the `cloudflared` tunnel is reporting as "Healthy" and "Active".

**Root Cause:** A Docker DNS mismatch. The Terraform configuration (`ingress.tf`) was attempting to route traffic to legacy container names from a previous Portainer environment (e.g., `app-observability-grafana-1`). In the automated GitOps deployment, the `app-` prefix was dropped. Cloudflare was passing the traffic successfully, but the Docker network couldn't find the requested container hostnames.

**Resolution:**
Update `terraform/ingress.tf` to match the exact container names generated by Docker Compose:

```hcl
# Inside terraform/ingress.tf -> ingress array
      {
        hostname = "grafana.${var.domain_name}"
        service  = "http://observability-grafana-1:3000"  # Removed 'app-'
      },
      {
        hostname = "wazuh.${var.domain_name}"
        service  = "[https://security-wazuh.dashboard-1:5601](https://security-wazuh.dashboard-1:5601)" # Removed 'app-'
        origin_request = {
          no_tls_verify = true
        }
      },
      {
        hostname = "n8n.${var.domain_name}"
        service  = "http://automation-n8n-1:5678" # Removed 'app-'
      }
```

**Apply the state:**
``` hcl
cd ~/sovereign-stack/terraform
terraform apply
```

## Issue 2: Locked out of Grafana (Invalid Credentials)

**Symptom:** Unable to log in to the Grafana dashboard using default credentials (`admin/admin`) or previous passwords.

**Root Cause:** The admin password was overwritten or lost. Additionally, older guides suggest using the `grafana-cli` executable to reset the password, but newer Grafana (`latest`) container images have merged this tool into the main binary, meaning `grafana-cli` returns an `executable file not found` error.

**Resolution:** Use the updated `grafana cli` (with a space) command directly against the running container to forcefully reset the internal SQLite database password.

- **Execute on Primary Host:**
```bash
docker exec -it observability-grafana-1 grafana cli admin reset-admin-password "SovereignStack_2026!"
```


**Verification:** The console will output `Admin password changed successfully ✔`. You can now log in to the UI using:
- **Username:** `admin`
- **Password:** `SovereignStack_2026!`
_(Note: The long-term architectural goal is to connect Grafana to Keycloak via OIDC, bypassing local passwords entirely)._
